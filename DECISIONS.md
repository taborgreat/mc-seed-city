# Decisions

Every judgement call made while building Seed City, one line each, dated. Newest at the bottom.
The design doc (`Seed_City_Design_Doc.pdf`) is the spec; where it is silent, the simplest option
that keeps every phase independently shippable wins, and it gets a line here.

- 2026-09-13: Target Minecraft **26.2**, the latest stable release at project start. Pinned in `gradle.properties`; never floated.
- 2026-09-13: **Java 25**, not the doc's Java 21. Mojang's version metadata for 26.2 requires Java 25 (`javaVersion.majorVersion = 25`), so 21 cannot run it. Language use stays conservative anyway.
- 2026-09-13: Loader **Fabric**, confirmed against the 2026 loader landscape. NeoForge only pays off for compatibility with large content-mod ecosystems, which this project does not need; Forge-loader support is a listed non-goal. Fabric's fast version tracking matters most while pinned to the newest release.
- 2026-09-13: Fabric Loader 0.19.5, Fabric API 0.160.0+26.2, Loom **1.17.20** (a release, not the template's `1.17-SNAPSHOT`, so builds are reproducible). Gradle 9.5.1 via the wrapper.
- 2026-09-13: **Mojang official mappings** (Loom's default; no Yarn). Verified against the remapped 26.2 jar: the doc's names are the mojmap names (`net.minecraft.resources.Identifier`, `net.minecraft.core.BlockPos`, `net.minecraft.world.level.block.Rotation`); cell NBT loads via `StructureTemplate`.
- 2026-09-13: Split environment source sets (`src/main` common+server, `src/client` client-only) as in the Fabric template. Keeps renderers from ever loading on a dedicated server.
- 2026-09-13: Unit tests are plain JUnit 5 for pure-logic packages (`card`, `grammar`, verifier models). In-world acceptance is Gametest; wiring the Gametest source set is the first Phase 0 task.
- 2026-09-13: No mixins yet. Prefer Fabric API events; any mixin added gets a line here with the reason.
- 2026-09-13: No license chosen. Tabor's call before the first Modrinth release; `fabric.mod.json` omits the field until then.
- 2026-09-13: Design doc PDF stays at the repo root as the spec of record. `CLAUDE.md` restates the rules an implementing agent must not break.
- 2026-09-13: Dev toolchain on this machine is a portable Temurin JDK 25 in `%USERPROFILE%\.jdks` with `JAVA_HOME` set as a user environment variable. No system-wide installer, no PATH change.
- 2026-09-13: **Cells are authored in code**, not hand-built in-game. Tabor knows little redstone, so the circuits live in `src/cellgen` (a plain-JVM DSL) and `gradlew genCells` emits the NBT + sidecar the spec requires. The runtime contract (structure NBT + JSON) is unchanged.
- 2026-09-13: **Verification runs in the real world**, not a headless simulator. The verifier parks probe blocks on in-ports, reads out-ports, and steps across server ticks; simulator-fidelity risk (doc 11) disappears because the simulator is Minecraft. Cost: verification is asynchronous and a cell is briefly live while tested. Revisit only if in-world verification proves too slow for Phase 1 growth rates.
- 2026-09-13: **Every cell is 7x7** in footprint with ports at y=1 on face centres. Makes the frontier a grid and port mating a direction+width check. Height is free.
- 2026-09-13: Added a `clock` truth model (free-running output must toggle) beyond the doc's list; the Clock Tower cannot be expressed with the others. Added optional sidecar field `settle`.
- 2026-09-13: `seedcity:probe` block exists only for the verifier: a constant 0-15 signal source. Never placed by the city, no item, no model.
- 2026-09-13: Added a `command` package for `/seedcity ...`; it is glue over the five interfaces, not a sixth.
- 2026-09-13: Acceptance tests are Fabric gametests in `src/gametest`, run by `gradlew runGameTest` and as part of `build`. One test per cell so a failure names the cell; a broken-cell test proves failures name a port.
- 2026-09-13: **Register contract**: transparent while clk high, holds while clk low, and `in` must not change in the same redstone tick as a falling clk edge (1 rt hold time, an inherent property of a gated comparator ring within a 7x7 footprint). The truth model tests write, hold, and input change as separate steps; Phase 3 card execution must respect the same rule.
- 2026-09-13: Docs that used to sit inside the data pack (`cells/README.md`) moved to `docs/`; resource paths may not contain capitals and Minecraft warned about them.
- 2026-09-13: **Layout is planned, not discovered.** `CityState` plans slots ahead of the builders in a fixed frontier order (distance from core, then x, then z) with a per-slot RNG seeded from the city seed, so the city depends only on (world seed, seed position) and never on builder timing. Builders execute the plan; they never choose.
- 2026-09-13: Core at slot (0,0), clock tower at (0,1), and a junction on the clock's output at (0,2) are placed by force; core and clock carry zero grammar weights. One clock per city (doc: "the Clock Tower is the root"); the forced junction guarantees the root branches three ways instead of dying in whatever the grammar drops on its single output.
- 2026-09-13: Grammar legality: out meets in of equal width, or a blank wall; out-out, in-in, and width mismatches are illegal; a face with no neighbour yet accepts anything. Weighting traces signal: the planner computes which planned slots are reachable from the clock, prefers choices whose input listens to a clocked output, prefers among those the ones with outputs facing open sides (so the clock spreads instead of dying in the first dead end), and a soft goal favours an actuator until a clocked one exists. The L0 default (clock through junctions and wires into drawbridges) emerges from hardware alone; the card machinery is Phase 3.
- 2026-09-13: **Materials are a ledger**, not items. The Seed starts the city with a configured stock; each task debits its cost at claim time; builders still fly to the nearest storage cell (or the core) before building so supply lines are visible. Collectors (later) credit the ledger. `unlimitedMaterials` config for testing.
- 2026-09-13: **Player builds are respected by geometry**: a slot is buildable only if its floor layer is solid and everything above it is air (or the Seed). Any foreign block blocks the slot for good. A per-block placed-by-player flag comes with the Warden (Phase 2), which needs it to decide what to revert.
- 2026-09-13: Builders finish a cell into a per-city **verification queue**; the verifier runs one cell at a time, never while a neighbour is under construction, and builders never claim a slot next to the cell under test. Probes are directional so they can sit in a neighbour's port position without back-feeding it. Known limit: verification is serialized per city and lags many fast builders; parallelise across non-adjacent slots if Phase 1 rates feel slow in play.
- 2026-09-13: Builder placeholder look is the vanilla allay model and texture; mob aesthetic is still an open question for Tabor. Builders fly (no terrain pathing pain on the boat, and they read as the city's organs hovering over the frontier).
- 2026-09-13: City state persists as `SavedData` per level under the command-storage data-fixer type (inert for our tag). Slots mid-build or mid-verify reload as planned and are simply re-run; already-correct blocks are skipped.
- 2026-09-13: Phase 1 gametest raises rates (40 blocks/s, 3 builders), pins the city seed via `citySeedOverride`, and asserts: a builder spawns, the core is built within two minutes, nine cells verify, the clock is built, and an actuator traces back to the clock. Determinism is asserted by planning the same seed twice. Real-rate runs are for play testing.
- 2026-09-13: **Frontier order is signal-first.** Slots that a clocked output already points at are planned before anything else, then re-plans, then the rest by distance. Ring order alone chose most cells before the clock could reach them, so the network could only grow one way.
- 2026-09-13: A cell that fails verification in place gets one retry before it is rejected; rejection clears everything above the floor (never the floor, or the slot becomes unbuildable forever) and re-plans the slot and its unbuilt dependants.
- 2026-09-13: Tabor proposed treating the city as a computer that physically grows its hardware per program (RAM, Compute, Storage districts; buses as data paths). Recorded as `docs/city-as-computer.md`. **Decided the same day**: (1) honesty rule holds, and a card is a plan until every piece of hardware it needs is built and verified; (2) words are **analog everywhere**, 0-15 on one wire, with a saturating comparator ALU (SUB native, NOT = 15 − a, ADD = 15 − ((15 − a) − b), OR = max, AND = min); (3) district zoning is **random per city** and must be readable from the architecture, so every district needs a recognisable look from the air. Governs Phases 3-5; Phase 2 unaffected.
- 2026-09-13: **Port width no longer gates mating** (deviation from doc 22.1 "with equal bits"). A 4-bit comparator port reads a 1-bit repeater as 15/0 and a 1-bit repeater reads any strength as on, so the physics already allow it; requiring equal widths split the city into a clock world and a bus world that could never touch (Tabor: "not much really seems connected"). Width stays in the sidecar as a semantic hint and same-width matings get a small weight bonus.
- 2026-09-13: **A live output is never wasted.** If any legal candidate would listen to a live neighbour output, the grammar chooses only among those; dead-end cells fill quiet slots. Straight-through continuations and same-width matings get bonuses so streets run straight. Sensors count as live sources for planning (the daylight network breathes with the day); the actuator goal and the Phase 1 test still trace to the clock specifically.
- 2026-09-13: Bus segments and daylight plazas were over-picked (a third of the boat); their district weights came down. Weights are the tuning knob for how a city looks and should stay in the cell definitions, not in code.
- 2026-09-13: **Wardens sweep blueprints, not ports.** The doc's "run Verify on each cell every 100 ticks" would flood the serialized verifier and disturb the running machine (probes gate values). Instead a Warden compares each built cell against its blueprint (block identity plus facing/delay/mode; never power, lit, extended), repairs whatever differs through the same BuildTask, and only then re-queues the cell for a real port verification. Pistons' moving blocks and probes are excluded from the comparison.
- 2026-09-13: **Fault Cells are planted by the planner**, not authored as separate cells. A faultable cell declares one `fault` block in its sidecar; once the clock reaches enough of the city the planner marks the next live wire/junction/bus slot as a fault and the builder leaves that block out. The slot's district gets no Warden while the fault is open (doc 7: "a dark district whose Warden is missing"). When a player restores the block, the cell is verified, counts as built, and the Warden arrives. Config: `faultsPerCity`, `faultAfterLiveCells`.
- 2026-09-13: Wardens fly at street height like Builders (shared `FlyingCityMob` base). The doc says "walks", but ground pathing across walled cells is a polish item, not a Phase 2 one. Placeholder look: iron golem.
- 2026-09-13: Sentinels are posted once per built register vault, reading the vault's `out` port; alertness is the strength read each tick; asleep at 0 (crouched, still), wandering and staring in between, hunting players at 15. Not replaced if killed, so killing the guards of a vault is a strategy. Placeholder look: husk. Any port can be bound via the API for later phases (Sentinel as `IN` source).
- 2026-09-13: **Config is per city.** `CityState.cfg()` returns a per-city override when set (tests, tools) and the global config otherwise; entities read config through their city. Needed because gametests run concurrently in one server and were fighting over a global override.
- 2026-09-13: **A city whose seed chunk is not entity-ticking does not tick** (doc 26: unloaded districts do not tick). Discovered the hard way: upkeep on an unloaded city spawned Wardens into chunks where it could not see them and did so every second.
- 2026-09-13: Placed-by-player tracking is deferred. Wardens revert everything inside a cell footprint regardless of who placed it (doc 24), and slot buildability already protects player builds outside cells; the flag is only needed when Collectors start mining terrain.
- 2026-09-13: Tabor's "language of growth" idea (compile to intent, cells as DNA, graph-first, invention by composition) assessed in `docs/language-of-growth.md`. Most of it is the existing design seen from another angle, which validates keeping twelve ops. Adopted: `/seedcity graph` (now), declarative truth specs instead of named Java models (Phase 4, needed for player-taught cells), `SET Rd Rs` (Phase 3), compound cells and a Foundry that composes verified cells against a wanted spec (direction, after Phase 5; the grid must allow multi-slot cells then). Rejected: per-building scripts (behaviour belongs to the five mobs), a second vocabulary, unbounded evolution.
- 2026-09-14: **Cards are books.** The Card Reader accepts a written book or a book and quill; pages joined by newlines are the card text. Book and quill is the in-game editor the doc asks for, with no GUI work. A punch-card-styled item can wrap the same content later.
- 2026-09-14: **Core terminals.** Until buses exist (Phase 4), the Core reaches a port by placing a Core-owned directional signal block (`seedcity:terminal`, the probe's class) just outside it, saving what was there and restoring it on eject. Values still live in register vaults and pass through ALU cells; terminals are the wires, not the memory. Integrity sweeps skip them.
- 2026-09-14: **One instruction per beat** of the physical Clock Tower, read from its output port every tick; `WAIT n` counts beats; no clock, no program. Micro-steps within an instruction run on ticks with generous settle times (24 ticks per ALU trip, 8 per register write).
- 2026-09-14: **ALU as microcode over three cells.** `alu_sub` (one subtract-mode comparator), `alu_not` (constant 15 on the rear via torch and repeater, input on the side), `alu_or` (two inputs driving one block, which takes the max). ADD = NOT, SUB, NOT; AND = SUB, SUB. Intermediates exist only on the wires between hardware steps. Truth models `sub`, `complement`, `max`, `min` added. Compute cells carry the Forge look (blackstone) and `setpiece: false`.
- 2026-09-14: Cards name cells by **build ordinal** (`drawbridge.2.in`), persisted per slot, so names never shift as the city grows. `type.*.port` drives every cell of a type: the first broadcast, and the seed of the GPU-district idea.
- 2026-09-14: A card whose hardware is missing is accepted as a **plan**; its needs become weighted-up cells for the grammar (`Grammar.choose` takes a wanted map, and a wanted cell competes with the live pool even in quiet slots). The plan re-resolves every two seconds and goes live on its own. Removing `NEED`'s L2 semantics from Phase 3: `NEED cell` is accepted and simply adds the cell to the wants.
- 2026-09-14: **L0 is the hardware default**, not a software card. The doc's built-in L0 card would need registers and ALU hardware to run honestly; the clock network the grammar grows already provides the idle choreography. `l0_default.card` became the example cards (`hold_bridges`, `blink`, `countdown`, `daylight`).
- 2026-09-14: The Reader wall is a text display entity inside the Core, updated once a second: program state, registers read from their vaults, clock, and card errors with line numbers. Cheaper and more legible than sign NBT.
- 2026-09-14: `SET Rd Rs` (register copy) is in, per docs/language-of-growth.md. Still twelve ops.
- 2026-09-14: **Zoning** (addendum decision 3): the core is the ring around the Seed; beyond it the city is cut into `sectors` (default 5) angular districts named forge, ram, storage, residential and plaza, shuffled and rotated by the city seed. Cells carry a weight per district, so registers grow only in RAM (or next to the core), ALU cells only in the Forge, warehouses mostly in Storage. Readable from the air, different every city. Wardens follow district names automatically.
- 2026-09-14: **Demand honours zoning.** A wanted cell is weighted up only where its district weight is non-zero; the earlier fallback that let a wanted cell go anywhere is gone. A card that needs an adder waits for the Forge sector to be reached, which is the doc's "in the Forge".
- 2026-09-14: **Couriers carry OUT and IN across districts** (doc 17): any target outside the core district gets a letter; a Courier picks it up at the Core, flies to the port and drives its terminal, or reads the port and flies the value back, and the program waits for it (a minute at most, then it takes 0). Repeated OUTs of an unchanged value do not post again. Targets in the core district are driven directly. Registers and ALU cells keep Core terminals for now.
- 2026-09-14: **Bus streets with taps and select lanes are deferred to Phase 5+.** Phase 4 made the addendum's honesty hold end to end (values in vaults, ops in cells, transport by Couriers or terminals) without the addressing hardware, which is a substantial cell-design project of its own. Terminals remain the Core's nerves until then.
- 2026-09-14: **Player blueprints** (doc 6.1): `/seedcity blueprint <cell>` gives an item; right-click a Builder with it and it builds that cell centred on where you stand, off the slot grid, through the same BuildTask and verifier. Free of material cost; not maintained by Wardens; not part of the plan. The breadboard (player-authored cells) is left for the Foundry work in docs/language-of-growth.md.
- 2026-09-14: **Vault cell**: a strongroom whose iron door opens only when its 4-bit input reads exactly 15 (a subtract-mode comparator takes 14 off, a torch two dust away being a constant 14) with a loot chest inside. Sidecar `loot` names a loot table applied to every chest a Builder places. Grows in Storage and plazas.
- 2026-09-14: Couriers and idle Builders now spawn and hover above the Core roof; spawning at seed+3 put them inside the roof and they could never leave. A reminder that cells are solid.
- 2026-09-14: **Mob art from PR #1 (Mcdrizzy) taken selectively, not merged.** The branch was cut from an old commit and rewrote CityState, BuildTask, the Warden (grounded) and more; a merge would have replaced current logic. Taken: the meshes, textures, glow layers, render states and renderers for Builder, Rectifier, Courier and Sentinel; spawn eggs; the exhibit-pose helper; the Blockbench sources and Python generators under `art/` and `tools/` (Pillow needed to regenerate). Left behind: the old server code, the Collector entity and its light block (Phase 5 will do the Collector against current CityState; its art is kept), the Bedrock packs, the showcase world, the vendored three.js and the preview HTML. The entities only gained synced presentation flags (building, carrying, repairing, alertness) and model-sized hitboxes.
- 2026-09-14: **The Warden is displayed as the Rectifier.** Entity id, class and doc name stay `warden`; the art, display name and spawn egg say Rectifier (Tabor). The Warden still flies.
- 2026-09-14: **The Redstone Rat is an approved extra outside the five mobs.** Tabor's friend's idea, kept distinct from the design doc: everything lives in `extra` (entity, spawn rule, creeper goal) plus the mod's only mixin, which adds a high-priority flee-from-rat goal to creepers (no Fabric event reaches a vanilla goal list). The rat is a Cat underneath so vanilla creepers already avoid it; no taming, breeding or sitting. Cities keep `maxRedstoneRats` (default 2) within 24 blocks of the Seed; 0 turns it off. It never touches city state or blocks.
- 2026-09-14: Builders and Rectifiers are immune to suffocation damage and hover above any block their body would share while working: a cell grows around the mob that builds it. Builders spawn above the Core roof (the lantern under the roof sat exactly where they used to appear, and a mob that starts inside a block never finds a path). Sentinel hitbox is 0.9 wide, not the model's 1.1, so it fits one-block gaps.
- 2026-09-14: **Phase 5 terrain** (doc 8): no biome or surface-rule registration; the city reads the land itself. A slot is surveyed (top ground per column), rejected for water, slope, warding, drop or anything unnatural, and floored at the median ground level or a neighbour's level within `terrainStep` so streets continue. Levels that differ never mate: the face is a wall. Site work (dig, foundation, cell, earth apron) is ordinary BuildTask steps the Builder performs, so blending is watchable and goes through the one mechanism. The apron copies the local surface block rather than querying the biome's surface rule, which is not exposed at runtime.
- 2026-09-14: **Collectors** (doc 20.1): gather orders come from a deficit rule (reserve per currency plus the planned frontier's cost); sources are natural blocks with an open face near the surface, found ring by ring in a fixed order; yields are a log 4 wood, a stone 2, an ore 8. Excavation during site work is salvaged too. Collectors are ground mobs (they leave the city) and spawn on real ground outside the footprint. A source that cannot be reached is shelved for five minutes.
- 2026-09-14: **Placed-by-player flag** (doc 20.1, 24) implemented as per-level saved data fed by Fabric's use-block and break events; a mark on air counts for nothing, so a failed placement never protects a slot. No mixin.
- 2026-09-14: **Warding is a block tag** (`#seedcity:warding`, default lodestone and crying obsidian) rather than a config string: data packs can extend it and it reads as Minecraft. Collectors test the straight line from the Seed to a source for warding blocks; a fence line therefore has to be closed to work, which is the intended puzzle.
- 2026-09-14: **L3 dreams** (doc 14): fragments are card snippets with placeholders (`$A` actuator port, `$S` sensor port, `$R` register, `$N` number, `$L` label) in `data/seedcity/fragments`; the Dreamer composes one to three usable ones into a loop, seeded by (city seed, dream number), and the card is kept only when it parses and binds live. Dreams are real written books in the reader, authored by "the city"; a superseded dream goes to a warehouse chest. Idle means no slot building or verifying for `dreamAfterSeconds`; a dream runs `dreamLengthSeconds` before the next. A player's card is never replaced.
- 2026-09-14: **Chunk cap is exact**: the span counts every chunk touched by every planned or built footprint, and a slot that would exceed it is blocked at planning time. The forced root is exempt (it exists before the cap is consulted).
- 2026-09-14: **Set-piece pass** (doc pillar 4, prompted by Tabor: "the drawbridge is just one block and a piston"). Same 7x7 footprint and ports, taller and legible: the clock tower is an 11-block spire whose torch ladder shows the beat climbing; the register is a vault with a four-lamp gauge on its wall (thresholds 1, >4, >7, >10 from a dust line that loses one per block); the drawbridge is a real deck over a water channel lifted whole by one sticky piston through a slime spine (Integrity now treats slime-carried blocks as dynamic); streets are paved with the wire in a glass groove and lantern posts; the warehouse has a roof crane; the plaza a fountain. The planner's clearance check uses the tallest cell the grammar can pick, and the chosen cell's own height at claim time, so a forced tower does not block every slot. Gametest areas are 14 blocks tall, which caps forced cells in tests.
- 2026-09-14: **Every city has a purpose from its first minute** (Tabor: "a grid of redstone machines with no purpose"). A city with an empty reader dreams at once (`dreamAtStart`): a live card if any fragment fits its hardware, otherwise an ambitious one written over one more actuator, sensor and vault than exist plus the ALU, which is accepted as a plan; the builders grow the plan's needs and it goes live when they stand. A running dream, after its length with an idle frontier, is followed by a bigger one the same way. So the RAM and Forge districts grow because the city's own programs ask for them, and a player takes a city over by inserting a card and hands it back by ejecting it.
- 2026-09-14: **A plan no longer silences the running program.** The card in the reader may be a plan while the previous program (its text is persisted as `running`) keeps executing; the plan replaces it the moment it binds live. This is what docs/cards.md promised and what dreaming bigger needs.
- 2026-09-14: **Bus, step one.** Faces may now carry several ports (`Port.along`, `Constraint.Facing`, `Grammar.portsOn`); ports meet when their position along the shared edge and their height agree. The bus is three lossless comparator lanes on the same 7x7 grid: select under the pavement (y=1, x=3), data out (y=3, x=2) and return (y=3, x=4) on top under glass. `bus_street` passes all three, `bus_end` turns data into return, and the Core grew a bus gate on its east face with terminal blocks inside it (`CityState.driveCoreLane`). Truth models `lanes` and `loopback` use six mixed vectors instead of every combination. Addressing: reads at select 1..N and writes at select N+something, decoded per vault from a dust snake (a repeater on the k-th dust is "at least k", two subtract comparators pick out exactly k); the rig test `BusDecodeTests` proves the decoder against the engine for all sixteen values. A composter as a constant proved order-sensitive and is not used.
- 2026-09-14: **Bus, step two: registers live on the bus.** Tabor lifted the 7x7 limit ("make it reliable and the most efficient redstone"), so cells may span several slots: a slot has an anchor, a footprint covers slots, the grammar sees per-candidate constraints on every outer face (`Grammar.choose` takes a room function) and the planner fits multi-slot footprints. The RAM vault is 7x6x14: a select decoder from a dust snake, a four-comparator ring, a write gate and a read gate onto the return lane. Addresses are read at select k and write at 6 or 8 (odd rows keep the decoder's relay column clear), truth models `ram_1_6` and `ram_2_8` written as one parametrised model. `bus_branch` taps select and data eastward and merges the eastern return. The Executor binds R0 and R1 to bus vaults by read address and reaches them only through the Core gate (`readReg`/`writeReg` as front-of-queue continuation steps, 90 ticks of settle per lane trip); the old `register_block` keeps zero weights for blueprints. A bus lane never mates a clock wire, and the grammar only grows a bus cell where a live lane arrives, so streets start at the Core gate and nowhere else; a wanted vault may stand right off the gate (core weight) or in RAM. Known limits, deliberately: two registers (decoders for k >= 3 collide with the relay columns), no readout port on a vault (the Reader wall shows what the program last saw; Sentinels do not guard bus vaults yet), ALU cells and OUT/IN still use terminals and Couriers.
- 2026-09-14: **Growing the bus is rule-driven, not luck.** Found while wiring the Executor to the bus: a deterministic draw put a dead end on the Core gate, then a wanted drawbridge, and a plan's wants never shrank (the plan was re-resolved every two seconds but the old Executor was kept). Now: while any bus cell is wanted a slot a bus lane reaches takes only bus cells, the wanted vault first; otherwise the program's wants beat everything (an idle street extension included), then fed cells, then the quiet fillers; the Core gate never takes a dead end or a vault (`Constraint.Facing` carries the neighbour's kind); while any bus cell is wanted, new bus cells are branches or the wanted vault; wants count cells already planned or under construction, so a city plants one bridge, not a row; a vault that stands or is planned on a bus still being built or verified is reported as connecting and wanted no further; and the re-resolved plan replaces the old one. Bus streets have a small weight in every district so a bus can cross a plaza on its way to RAM; vaults keep zero weight outside RAM and the core ring. `CityState.explain` reports why a cell would or would not be planned at a slot, and the planner logs when a bus lane dead-ends into a non-bus cell.
- 2026-09-14: Builders count as arrived when they are over the target column within eight blocks of height after three seconds of trying. The exact point two blocks above a block near a ceiling, a roof or a tree canopy was unreachable, the Builder gave the task up after `abandonSeconds`, reclaimed it and repeated forever with the ledger refunded and re-spent (the intermittent "clock tower stuck BUILDING" under the gametest ceiling). Placement never needed the exact point.
- 2026-09-14: **Street profile** (Tabor: "the glass paths don't flow"). Every cell a wire passes through keeps one profile: the wire at floor level in a one-wide groove, brick kerbs beside it, a glass lid one block above the paving. The inverter dropped its raised brick box for that profile (its lamp sits in the lid over the torch) and the drawbridge's north bank carries the groove and lid on to the water. The clock tower is 21 tall so it is visible from anywhere in a city; the gametest boat structure is 32 tall so forced cells no longer meet the test ceiling. Bridges that span real gaps and oriented placement are the next steps of the same pass, driven by Tabor's screenshots.
- 2026-09-15: **Purpose pass, step one** (Tabor: "I don't know what this computer is for"). The doc's own diagnosis applies: a machine with nothing worth controlling. Three cells and two cards start the fix. `gatehouse` is the first defensive structure a program controls (a portcullis on the street, any value above 0 shuts it); `footfall_plaza` is the first sensor that reads the player (gold plates, one player reads 1), so a card can answer to who walks where; `curfew` and `alarm` are the example cards that use them. Streets became walkable: paving is full blocks and the wire sits in a groove under an iron trapdoor grate flush with the paving (you walk over the wire and see it), the inverter and the drawbridge bank share the profile. `garden_lane` is a street whose verges are structure void: `Cell` records void positions, site work (`Terrain.clears`, `foundation`) leaves those columns alone, and Integrity never looked at non-blueprint blocks, so the land between buildings stays land (Tabor: "let it breathe, half managed spaces"). - 2026-09-15: **Two languages, one graph** proposed in `docs/two-languages.md` (Tabor: an operating system for the world above, a graph of needs and capabilities below, the city as the compiled architecture). - 2026-09-15: **Cells sit in the land, not on it** (Tabor: paths "should be lower in ground closer to terrain matching and digging down"). Local y=1 of every cell (paving, wire, doorway) is ground level: a slot's origin is one below the lowest ground under it, higher ground inside the slot is dug away, and the Core origin moved to Seed minus two with the Seed standing on a paved chamber floor at (3,2,3). The surface row a cell sinks into counts as buildable; a planted fault also digs its hole; the apron banks down from the paving. The terrain test now asserts that no cell stands more than `terrainStep` above the lowest ground under it instead of counting apron blocks, which are now rare by design.
- 2026-09-15: **Avenues and doors** (Tabor: paths and bridges "generate with no logic"). Two sidecar fields: `street` (walkable through) and `doors` (faces a person enters by). The two axes through the Core are avenues that take only street cells, with a fallback to the whole library if no street fits, so a walk from the edge to the Core always exists and the city reads as a cross. Buildings turn their doors toward streets through a weight factor (3 on a street, 1.25 on an open side, 0.3 against a building); `Constraint` carries whether the neighbour is a street. The grammar computes what the program wants from the whole library even when a slot allows only a subset, which the first attempt got wrong and a drawbridge took the Core gate. `avenuesAreStreets` checks the preview plan.
- 2026-09-15: **Walls, gates and river bridges** (Tabor: "gates in front of the core or around edges/walls", "finally improve the bridge logic"). Sidecar `backs` puts walls on the perimeter ring with their backs to the world (`city_wall`, `city_wall_corner`, structure void inside so the land stays); gate sites are the avenue slots at the Core's ring and at the city's edge, where a gate is weighted ten times, so a city grows a wall with gates where its avenues leave and gates in front of the Core. Sidecar `wet` admits a cell only on water: `fitSlot` surveys a watery slot at the water's level for wet cells, `river_bridge` keeps its channel and bed as structure void so the river flows under the deck and its piers are founded to the bed, and an avenue that meets a river crosses it on one. Dreams never ask for a wet cell. Found on the way: **a neighbour's output pointed at a blank wall powers that wall block and leaks into wiring behind it** (the forced junction's west output into the RAM vault's decoder snake made a vault fail verification and get re-planned). The grammar now refuses an output against a wall with a component behind it, in both directions (`Constraint.sensitive`, `Grammar.sensitive`), and the vault's long sides became windows.
